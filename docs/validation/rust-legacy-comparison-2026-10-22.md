# Legacy comparison and arrangement checkpoint

The native reference menu now offers Automatic, Side by side and Stacked arrangements. Automatic keeps the responsive layout used before this checkpoint. The explicit choices override that width-based decision. Arrangement changes restore each pane's canonical anchor in its new geometry, and the selected arrangement is included in workspace comparison saves. Older native comparison records without this field retain Automatic.

Loading a workspace without a native comparison preference now adapts enabled Flutter split settings. The secondary tab is resolved against the restored workspace readings, retaining its document, page, zoom, paper theme, rotation, margins and saved vertical scroll offset. The offset is applied once after the PDF geometry is available; subsequent native snapshots use canonical PDF coordinates. A vertical legacy divider maps to Side by side, and a horizontal divider maps to Stacked. Ratio and page/zoom synchronization are retained.

This conversion does not write during loading. SQLite remains at version 11 and the original split JSON, including unknown fields, remains unchanged. A native comparison preference takes priority, including an explicit null that records closing the reference. Invalid or unavailable legacy references and unsupported overlay settings produce a recoverable warning while retaining the main readings and original settings. The Flutter split model persisted these fields, but its arrangement was not connected to the visible legacy reader; this is an adapter for stored state, not a claim that Flutter displayed those layouts.

One existing storage test and one existing native scenario were extended. `all_eleven_historical_schemas_preserve_ids_relationships_and_preferences` passed with assertions for the horizontal legacy mapping, secondary document, ratio and scroll offset; it also verifies that an unsupported overlay returns a warning while the primary readings remain loadable. Its existing SQL checks confirm preservation of the original split and unknown query fields. The native `workspaces` scenario restored a Stacked comparison, waited for the actual stacked presentation, switched to Side by side, and verified the committed workspace arrangement through SQLite. The final [synthetic capture](../screenshots/rust-legacy-comparison/workspaces.png) and control record retain the side-by-side result. The native binary compiled. No standalone tests or broad suite were added.

Physical acceptance of imported profiles, secondary reader tools, overlays, accessibility and performance acceptance, and Release packaging remain pending.
