# Native PDF contents and destination navigation

The reader now connects its Contents tab to the asynchronous PDF outline command.
It displays the original chapter hierarchy, supports independently folded branches,
and virtualizes visible rows. Headings without local destinations remain headings.
Loading, empty, failure and retry states have Spanish and English copy. Chapter
buttons preserve their full accessible labels and hover text when visually truncated.
The compact drawer omits the explanatory heading and uses the existing Navigator
control to close, leaving room for chapters at enlarged text sizes.

Replies must match both document and request identity. Changing documents cancels
the pending read and releases the previous shared outline. A domain boundary now
rejects forward, self and out-of-range parent indices before UI traversal. Tests
cover stale and cancelled replies, nested folding, cancellation on drop, malformed
parents and reservation release.

Selecting a chapter queues its complete destination for the actual reader viewport.
Resolution uses the current effective zoom, native crop/rotation coordinates and
viewport PDF point, including null destination parameters. The proposed result is
validated before changing position and preferences. The canonical navigation model
records the jump, so existing history commands can return to it. Destination zoom
is preserved when loading or changing reader preferences, including values outside
the manual zoom control's range. Unsupported floating-point representations fail
before applying the destination. Finite canvas edges still constrain scrolling.

The page update and preference save are separate actor commands. This does not
prove atomic durable restoration of per-tab position and zoom across process death.
The broader continuity requirement remains open.

## PDFium lifecycle correction

Initial validation exposed repeated worker startup failures. The pinned
pdfium-render release keeps its bindings process-wide and refuses a second bind.
A guarded binding module now initializes the explicitly selected canonical DLL once,
then reuses those bindings only for the same path. Missing or different paths are
rejected. There is no fallback to a system PDFium library. Initialization is serialized;
the dependency's thread-safe bindings remain enabled. A regression test checks
reuse after dropping a Pdfium instance and rejection of alternate and missing paths.
The existing native test suites exercise repeated worker starts in one process.

## Native presentation evidence

The isolated synthetic fixture is generated by
`tool/create_rust_outline_fixture.py`. It creates a three-page study document with
parent chapters and XYZ child destinations, and records its source hash. It does
not overwrite the existing demo fixture or open a personal library.

First-pass and confirmation captures cover dark English, light Spanish and the
640×480 requested viewport at 200% text zoom. Review corrected excessive button
borders, inconsistent branch indentation and a compact header that hid chapters.
The final compact capture exposes a chapter without scrolling the entire drawer.
The separate outline-passage case calls the same destination handler as chapter
selection and renders page 2 at 150% with the intended passage at the top. It is
synthetic action evidence, not a physical mouse or Narrator acceptance test.

Captures, control bounds, source hashes and executable hashes remain in the ignored
`build/rust-visual/outline-confirmation` and `build/rust-visual/outline-navigation`
directories. No screenshots, personal PDFs, databases or executable artifacts are
part of this source checkpoint.

Validation commands:

```text
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
cargo fmt --all -- --check
cargo rustc -p yamantaka --locked -- -o build/verification/yamantaka-outline-preview.exe
```

The final workspace run passed 163 tests. Clippy with warnings denied and the
format check passed. The executable compiled and all four native capture cases
completed with exit code zero.

The alternate executable leaves the user's open demonstration window untouched.
Large-outline latency, physical monitor DPI, keyboard/Narrator interaction,
in-document search, thumbnail navigation, links and full release acceptance remain
pending. This checkpoint advances the rewrite; it does not complete it.
