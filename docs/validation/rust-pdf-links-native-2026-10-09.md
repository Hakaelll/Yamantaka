# Native reader link presentation and keyboard navigation

Date: 2026-10-09

## Scope and artifact

A dedicated three-page study fixture adds one internal link per page. It is generated by `tool/create_rust_links_fixture.py` with ReportLab's invariant output and contains no personal document data. Original PDF extraction, cancellation and payload accounting are covered separately in [the extraction report](rust-pdf-links-extraction-2026-10-09.md).

The alternate executable `build/verification/yamantaka-links-preview.exe` was built from the current Rust UI. Five isolated native captures are under `build/rust-visual/links-native`, with exact executable, Cargo.lock, source, PNG and control-record hashes in `capture-manifest.json`.

Verified manifest SHA-256: `8C27DB86F07FE0081A3DFB337D707C3DBC34D8AD66296BD8C56413A71EA31B06`.

## Executed evidence

| Capture | Evidence |
| --- | --- |
| links-dark | Page 1, focused internal region, native wgpu page presentation |
| links-light-es | Page 1, light Spanish controls and localized destination semantics |
| links-small-200 | 640 x 480 requested window, interface text at 200%, focused region retained within its clip |
| links-keyboard | Synthetic Enter event activates the production focused link and navigates from page 1 to page 2; the destination chapter is visible and recorded page index is 1 |
| links-rotated | User rotation of 90 degrees; the focus contour follows the rotated document region |

The native keyboard case injects an egui input event through eframe's raw-input hook, guarded by both demo mode and capture output. It uses the production interaction control and destination resolver. It is not an OS keyboard, Narrator or physical-device certification. Pointer, Enter, Space and gap behavior also have an executed egui input regression test; an OS pointer click was not performed during these captures.

Each final capture reports one ready page and one internal link, native-wgpu presentation and 712 Text bytes at the capture point. These bytes describe this synthetic document only and exclude opaque native allocations. All recorded link controls are enabled and fit inside their clips. Hash verification checked every manifest source, the executable, Cargo.lock and every PNG/control record.

Visual inspection used three initial views and three confirmation views after correcting the synthetic document title and adding explicit page/zoom evidence. The final light, rotated and keyboard captures were inspected. No additional appearance-polishing loop was performed.

All 198 workspace tests, warning-denied Clippy and formatting checks passed. Local logs are `build/verification/pdf-links-native-tests.log` and `build/verification/pdf-links-native-clippy.log`.

## Remaining acceptance

Broader mouse and keyboard sequences, back/forward history after link activation, rapid document/layout changes, continuous-layout small-zoom performance, physical DPI, Narrator and multi-monitor validation remain pending. At 200% interface text, fit-page PDF text can remain small; document zoom is independent of interface text scaling. External URI links and confirmation are still pending. This checkpoint does not satisfy the full rewrite or release acceptance.
