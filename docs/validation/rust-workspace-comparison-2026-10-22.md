# Saved workspace comparison checkpoint

Saving or updating a workspace now captures the native reference document, canonical page and PDF point, zoom mode and level, paper theme, rotation, margins, divider ratio and following options. The reference may use the main PDF or another catalogue document. The reference does not consume another saved reading slot, and opening it still uses the existing two-document admission and confirmation lifecycle.

Opening a workspace restores its main reading first, then opens and confirms the reference before applying its context. Recovery after startup uses the same path when the saved workspace revision and queue still match. User changes made while startup recovery is pending prevent applying the saved comparison. A missing reference, opening failure or cancelled reference password preserves the main reading. Failed recovery does not automatically replace the stored comparison with its fallback view. Broader physical restart and failure-path acceptance remains pending.

While a workspace is linked, reference changes save after 600 ms without another change. These revision-guarded asynchronous writes update only the comparison extension, preserving other library settings and unknown query fields. Page scrolling does not continuously write to SQLite. Closing flushes pending user changes; a reference still awaiting restoration is not treated as a user edit. A failed save pauses automatic workspace writes and reports the error, preserving the current readings.

The context lives in the `yamantakaRustComparison` member of the existing workspace query JSON. SQLite remains at version 11. Existing Flutter split JSON remains unchanged. Its historical split settings are preserved, but converting those settings into the new native comparison still remains pending. The new extension validates IDs, finite coordinates and zoom, margins, rotation and divider limits before accepting it.

Validation used one existing storage test and one existing native scenario; no standalone tests or broad suite were added. `all_eleven_historical_schemas_preserve_ids_relationships_and_preferences` passed with its workspace helper extended to verify comparison round-tripping, startup loading, stale-write rejection, invalid-coordinate rejection, removal and preservation of unknown query fields. The native `workspaces` scenario restored another PDF at page 2, 80% zoom, a 60% divider, sepia paper and 90-degree rotation. It then enabled zoom following and moved the divider to 55%, checked the committed SQLite state, and completed the existing queue, duplication and deletion recovery flow. The [synthetic native capture](../screenshots/rust-workspace-comparison/workspaces.png) and adjacent control record retain the result.

Secondary reader tools, historical split conversion, comparison overlays, full accessibility/performance acceptance and Release packaging remain pending.
