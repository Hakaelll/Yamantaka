# Workspace view and queue binding

Saving or explicitly updating a workspace now records the current text query, favorite/missing/modified/reading filters, tag and collection selection, smart view, sort/direction, grouping, cover size, list/cover choice, inspector choice and concentration mode. Unknown query properties survive updates. Existing v11 and backup v9 formats remain unchanged. The domain reuses the workspace's installed serde_json dependency for the lossless query contract.

Opening applies these values only after the intended live tab plan has been adopted and its reader preferences have loaded. Failed reader opening preserves the previous library and concentration context. Collection and tag labels are revalidated through the existing scoped actor commands. Compact cover density reuses the same 3D book renderer; list row geometry is unchanged.

F8 or Reading options → Focus mode hides the reader toolbar and navigator while preserving panel selection. A floating exit button and F8 restore them. Annotation preparation and page interaction remain available. No decorative motion or loading screen is added.

The explicitly opened workspace becomes the active in-process binding. Changes to reading membership/order, queue values, active document and concentration mode save through the existing actor. Replies carry the committed workspace header and revision. A reply acknowledges only its submitted snapshot, allowing a newer local change to be written afterward. Conflicting or failed writes pause automatic saving and retain current continuity. Explicitly updating or reopening the workspace can establish a fresh revision. Ordinary window closing waits while a named-workspace write or unsaved bound context remains. A write failure cancels that deferred close so the error can be seen.

Validation stayed within the feature. The existing retained compatibility case passed with checks for unknown query preservation, saved view values and the exact revision returned by concentration writes. One native synthetic scenario exercises the connected management flow, deliberately changes the live view before restoration, opens a real fixture PDF, and checks restored view/concentration values. It then changes the active queue entry and concentration mode, waits for actor acknowledgements, and reopens the file-backed database through a separate read-only connection to verify those writes. Its [capture](../screenshots/rust-workspace-context/workspaces.png) shows the native workspace dialog over the concentration reader. An initial SQL parameter-count failure was corrected before the successful runs. No broad test battery was run.

Binding after application restart, automatic default opening, split/comparison restoration, deletion undo, explicit close-during-write interaction, physical F8/mouse acceptance and the complete accessibility/performance matrix remain pending. This checkpoint does not establish complete workspace parity or Release readiness.
